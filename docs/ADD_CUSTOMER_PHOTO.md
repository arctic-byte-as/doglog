# Add customer photo picker (DL-056)

Add customer now uses DogProfileImageField and the existing camera/library/crop dialog instead of a photo URL input. The cropped JPEG stays in browser memory, with a preview, until Create customer is selected. Removing the photo or choosing an avatar clears the staged file. Blob preview URLs are revoked when replaced or unmounted. Creation is disabled while the photo is being prepared, and a failed submission retains the form and photo for retry.

The admin creation endpoint accepts multipart `details` JSON plus an optional `file`, while preserving its existing JSON contract. Authorization and required-field/duplicate-customer validation precede upload. A customer UUID is allocated before upload so the saved image uses the same customer-owned storage folder as later customer/trainer photo changes. The customer and dog records are then created in the existing database transaction with the resulting image URL. No schema or environment changes are required. As with other uploads, an exceptional database failure after successful storage upload can leave an unused image object; account/dog creation remains transactional.

Validation: optimized build, TypeScript/lint and diff checks pass (existing DogListItem img warning). Browser checks at 390/1440px confirm the shared picker fits. A temporary development admin/customer workflow verifies no early upload/account creation, cropped photo persistence under the new customer's folder, retained photo/details after simulated submission failure and successful retry, invalid-file rejection before account creation, and anonymous-access rejection. Temporary records and storage images were removed. Physical camera capture was not exercised. Included in the approved production release.
