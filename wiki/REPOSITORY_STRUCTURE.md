# Repository Structure

## Principles

- Keep files small
- Group by feature when possible
- Avoid deep nesting
- Keep business logic isolated

---

# Suggested Structure

/app
  /(dashboard)
  /(auth)
  /api

/components
/features
/lib
/server
/prisma
/tests
/docs

---

# Naming Conventions

## Components
PascalCase

## Utilities
camelCase

## Database Models
Singular nouns

---

# Documentation Standards

Every major architectural decision should be documented.

Update:
- PROJECT_FOUNDATION.md
- SYSTEM_ARCHITECTURE.md
- DATABASE_DESIGN.md

when major changes occur.
